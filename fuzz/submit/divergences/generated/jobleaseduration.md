C++ enforces its own 20-second floor on ONE PROC. `job_lease_duration = 1` with `queue 3` gives proc 0 the corrected 20 and procs 1 and 2 the uncorrected 1, out of one submit file: already_warned_job_lease_too_small is a warning-dedup flag, and it gates the VALUE CORRECTION as well as the warning (submit_utils.cpp -- declared ~667, tested 3598, set 3603, never reset), so every proc after the first keeps a lease the code has just said is not allowed. Go applies the floor to every proc. Reproducing the drift would mean reproducing the flag.
Sweep cannot prove this: whether the generator writes a small job_lease_duration with more than one proc depends on the oracle's keyword table, so it reproduces against one condor build and not another; TestJobLeaseFloorAcrossProcs compares the value proc by proc, on both sides.
